# 拾句二期优化评估｜一页结论与阶段记录

日期：2026-10-26。状态：评估交付，等待方案确认；产品未修改。

## 一页结论

**下一轮先补齐现有翻译闭环和三应用验收，再完善 API 等待边界，最后按分段耗时做最小提速。当前证据不支持重写框架。**

拾句已有翻译、问 AI、解释/润色、追问、流式、停止/重试、双窗、边缘缩放、逐条复制、100 条记录和 Windows 加密 Key，无需重新开发。代码与本轮验证证据详见 [对照报告第 2 节](../reference/textlens-review.md#2-拾句已有无需重做)。完整桌面问答、微信和 WPS 验收仍未完成。

TextLens 值得学习的是共享 HTTP Client、分阶段超时、网络读取与 IPC 分离、就绪快照及事件恢复、正文局部订阅和 Windows 失焦归属确认。它的 store 即时追加、显示层再做动画，完成时直接显示全部；动画不能证明模型快。证据为固定提交的 `actions.rs:648-664,1050-1099`、`openai_transport.rs:35-49`、`actionEventStore.ts:101-126`、`ResultApp.tsx:174-218`、`useSmoothStreamText.ts:52-101`、`windows.rs:1390-1443`，详见 [报告第 3～5 节](../reference/textlens-review.md#3-ai-请求对照)。

| 优先 | 用户收益、具体改动 | 代价与风险 | 验收 |
|---|---|---|---|
| 1 当前闭环与真实可用 | 修复翻译语言标签更新但未重译；用公开材料验收 Chrome、微信、WPS 的完整问答与双窗操作 | 约 0.5～1 天修改，另加真实验收；防重复请求、串答与误停后台任务 | 同语言不请求，不同语言仅重译一次且保留同一记录；三应用自动/备用取词分别记录，翻译到追问/复制、停止、菜单/拖边均有结果 |
| 2 API 可靠性 | 区分请求头、首正文、思考活动、流空闲、总超时，增加明确上下文上限 | 约 1～2 天；防误杀慢请求和静默丢历史，不照搬第三方阈值 | 心跳无正文、仅思考、断流、429、取消及超限均有确定行为；保留部分正文、独立停止和用户重试；补真实服务正常样本 |
| 3 分段测量后优化 | 记录点击、窗口、请求、首正文到达/上屏、完成；有证据才缩短首段发布等待或减少全量快照/渲染 | 约 1 天诊断，必要小改另估 0.5～1 天；常驻进程/窗口复用有生命周期风险 | 同服务模型参数公开文本各至少 3 次，留逐次样本；真实首字与本地呈现分开，不以动画或模拟流宣称模型提速 |

以上为估算与待确认方案，完整风险与验收见 [报告第 7 节](../reference/textlens-review.md#7-下一轮测速方案与验收门槛)。

### 授权与方案

用户随后明确要求修复评估发现的语言切换问题，范围转为该问题的本地实现。沿用先前提出的最小方案：不同目标语言在同一记录重译，选择相同语言不请求，生成期间禁用语言切换，停止或完成后恢复。没有授权实施其余二期建议或发布新版本。

### 实现与验证

- 根因：语言命令只修改字段，未发起生成。`TaskManager.setLanguage` 现在校验翻译问答与当前运行状态，再走既有重试路径，生成新 requestId，在同一记录替换末轮译文、更新主动请求时间并保留草稿。现有请求身份防护过滤旧输出；后台任务保持独立。
- 主进程对语言命令处理重译 Promise；界面禁用生成中的语言选择，关闭已打开菜单，并给出悬停说明。后端仍校验，避免界面状态延迟或绕过控件导致误改。
- 先新增回归测试，运行时出现 3 处预期失败，证实未触发重译和运行期缺保护。首次针对性命令意外还发现历史副本测试，随后使用 `--dir tests` 限定根目录；历史测试结果不作本次证据。
- 修复后 14 项根目录任务测试通过，全量 11 个文件共 59 项测试通过；类型检查与开发构建通过。新增测试覆盖同记录、新目标语言、同语言无请求/不改排序、草稿和后台任务、旧事件、防运行中切换、停止后切换及失败后重试。
- requesting-code-review 独立只读审查未发现范围内的正确性或回归问题；审查者没有声称执行桌面验证。
- 隔离原生窗口测试脚本为 `.runtime/language-switch-check.mjs`，仅用公开记录、占位凭据和本机模拟 API，未读取用户配置。Playwright Electron 启动两次失败，改为直接启动后进程退出码为 2147483651（0x80000003）；到此记录边界，不继续重复启动。不把脚本存在当作集成测试通过。
- 因此真实菜单点击、真实模型重译仍未验收。安装版与免安装版保持原样，没有更新已发布资产、版本号、依赖或模型配置；没有提交、推送或发布。
- PRDS/UI.md、PRDS/PRD.md 和项目 AGENTS.md 已同步当前有效规则。前文评估阶段的“未改产品”只描述当时交付，不再表示后续修复阶段无源码改动；参考报告继续作为固定基线的审查快照。

### 用户补充关注点与边界

用户追问多 App 划词、工具条位置与其他 Agent 接入是否已评估。结论是三者证据并不齐全：多 App 已有代码机制对照但仍缺三应用真实矩阵；工具条当前使用选区末端坐标、显示器工作区和上下翻转避边（`src/main/desktop.ts:31-34,86-96`，`src/main/window-placement.ts:2-11`），尚未验证反向划词、遮挡、混合 DPI 和多屏体验；Agent 仅审查了当前 Codex 与兼容 API，不代表其他 Agent 可接入。其他 Agent 的登录、流式/取消、临时会话、上下文、工具权限和成本需要候选明确后分别验证。该补充没有扩大本次代码修复范围。
