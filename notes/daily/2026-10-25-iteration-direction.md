# 本地迭代方向讨论

## 当前有效决定

保持本地试用，不上线、不公开发布。当前核心体验问题是回答开始前约十秒的等待。阶段六仅推进本地验收；一期未完成项仍需验收，之后开展二期优化。

## 二期候选（尚未实施）

- 优先排查与改善首字等待，分别记录短句、段落和追问的耗时，不把加载提示作为提速结果。
- 结果窗允许从边缘调整大小，配合最小尺寸、屏幕边界与输入区适配。
- 提问与回答均支持单独复制；长回答的选中复制及排版需要评审。
- 设置用日常语言解释用途；常用偏好与高级 Codex 路径分开，避免检查动作保存无关设置。
- 研究用户主动触发的“到 Codex 继续”。当前只是方案核对，没有加入按钮、发送用户内容或打开新对话。

## Codex 跳转的证据与边界

本机 npm CLI 帮助列出 app 和 resume。app 是桌面应用启动入口，resume 是终端会话续接入口；不能据此认定 app 支持打开任意指定 thread。

官方文档 https://learn.chatgpt.com/docs/reference/commands 列出 codex://threads/<thread-id>、codex://threads/new 以及新对话的 prompt 参数。prompt 的作用是预填输入框，不是自动发送或导入原生消息历史。

当前助手以 ephemeral:true 创建线程，完成后关闭进程，且没有保存原生 thread ID。要做指定原线程接续，必须先验证持久化、身份保存及当前 Windows 桌面端加载行为。普通划词不应因此自动堆积长期聊天。

可先用公开文本验证“点击继续→创建新对话草稿并携带整理后的上下文”，明确为带上下文的新对话；如果要保留原生逐条消息历史或原线程身份，需单独技术验证。桌面跳转本身不会缩短浮窗中的模型首字等待。
