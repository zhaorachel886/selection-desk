# 回答可读性与复制反馈

## 范围与依据

用户确认 Chrome、微信、WPS 均可调用，属于触发链路的用户实测反馈；不据此推定所有位置、耗时和完整回答验收通过。用户反馈正文露出 Markdown 标记、解释冗长重复选区、复制成功提示遮挡正文。

## 实现

- 原正文只分割空行后放入 p，未解析 Markdown。改用固定版本 react-markdown 10.1.0，支持 CommonMark 标题、列表、加粗、引用与代码；保持字号与紧凑间距。按完整累计正文更新，不加打字机延时。基础渲染不含 GFM 表格、公式和语法高亮。
- 使用 React 元素渲染，跳过原始 HTML；链接及图片呈现为文字，避免导航或外部图片加载。复制仍使用原始回答文本。
- API 与 Codex 共用解释规范：直接解释，首答默认 2～3 句，不复述选区，按需给一个短例子，不主动铺陈背景及用途清单；追问按需展开。没有截断模型正文。
- 复制原文、问题、回答成功均保持安静；失败分支继续显示错误。
- 新增依赖及锁文件、第三方运行依赖清单同步。参考官方文档 https://github.com/remarkjs/react-markdown 。运行依赖 npm audit --omit=dev 为 0 项；完整依赖树仍有开发依赖历史告警，未执行 audit fix 或扩大升级范围。

## 验证

- 新增 5 项测试先失败再通过，覆盖格式语义、安全边界、未闭合流式文本及两条来源的解释要求。全量 88 项测试、类型检查、构建通过。
- 隔离 Electron 使用专门公开记录，标题、加粗、编号列表、引用、代码块及窄窗口无横向溢出检查通过；复制问题/回答后无提示，截图已检查。
- 新目录版同一原生检查通过；包内主进程、前端 JS/CSS 与当前构建逐字节一致，未发现用户配置、历史或 Key 文件。首次目录版检查误选隐藏预加载工具条而超时，测试改为按窗口状态选择历史页后通过。
- 失败提示保留的证据为代码审查；尝试在测试页替换只读 contextBridge 方法无效，未将其声称为实际失败场景验证。
- 诊断与截图位于 `.runtime/answer-format-check/`。没有使用真实模型、用户凭据或用户记录；提示词效果仍需用户现有 GLM 配置复验。
