# 拾句工具条 UI 审查与修正

日期：2026-10-26。范围：工具条定位、尺寸、透明圆角及相关窗口交互。依据 frontend-design-pro 的 audit/harden 方法，沿用项目已确认的系统字体、14px 标签、18px 图标与紧凑布局。

## 审查结论

| 优先级与问题 | 证据 | 修正及状态 |
|---|---|---|
| P1 原生窗口与内容高度不一致，圆角外出现白底 | 原试用包实测原生内容 228×48，CSS 工具条 228×38，原生最小值 228×47；原设置使用不透明白底。代码位置 `src/main/desktop.ts:95,102`、`src/renderer/styles.css:4` | 工具条原生底色透明、关闭原生阴影、清除默认最小尺寸后按内容设置大小，CSS 填满实际内容区。125% 缩放实测内容及工具条均 228×40，圆角像素 alpha=0，无多余底部条带；系统像素取整使实际高度略高于 38 的目标值 |
| P1 只靠选区终点摆放，无法表达灵活避让 | 原工具条共用结果窗下方放置策略，且选区仅为终点 1×1。当前专用实现位于 `src/main/window-placement.ts:14-31`、`src/main/desktop.ts:89-98` | 工具条与结果窗定位分离；优先选区上方居中，不足则下方，横向收回工作区，最终完整可见。真实 Windows 窗口的四角及中央测试通过，输入为固定公开坐标，不宣称真实划词完成验收 |
| P2 多行文字首末端点不能证明左右留白 | `src/main/selection-anchor.ts:17-29` 的端点信息不能包含所有折行宽度；鼠标拖选也没有实际字形矩形 | 保留可用的纵向跨度，对估计横向边界标记 horizontalBoundsKnown=false，不把端点间狭窄范围当作安全侧边。上下都无空间时采用最小重叠的工作区内退路，不承诺所有极端长选区都能完全不遮挡。已补长折行选区测试 |
| P2 跨显示器时可能选错工具条所属屏幕 | 新增测试中选区从负坐标显示器跨到主屏，修正前工具条 x=-234，落回起点屏幕。代码位置 `src/main/desktop.ts:90-91` | 使用选区末端锚点选显示器，再用选区区域计算该屏内位置。修正后测试通过；不同 DPI 的真实多屏仍待复验 |

## 有效交互规则

- 工具条优先在选区上方居中，上方不足时翻到下方，左右边缘收回屏幕工作区。
- 只有完整、可靠的横向边界才可据此判断侧边空间；当前 selection-hook 端点不能给出这样的保证。超大选区优先完整显示工具条、尽量减少遮挡。
- 工具条跟随选区末端所在显示器。原生坐标按既有规则转 DIP；不重复缩放，不把鼠标级事件的零文字边界当作选区。
- 目标高度 38 逻辑像素，允许 Windows 缩放取整造成少量差异；实际内容区与 CSS 工具条必须对齐，圆角外保持透明。
- 保留已修正的预加载、重复使用、页面加载完成/首次绘制双路径就绪、防收起后复活及崩溃恢复，不更改翻译或问 AI 的请求规则。
