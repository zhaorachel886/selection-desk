# 拾句：技术方案

日期：2026-10-22；状态：方案已确认，实际链路待开发验证。

## 技术组成

采用 Electron + React + TypeScript 构建 Windows 桌面工具。主进程管理取词、窗口、任务和本机记录；渲染界面通过受限 preload 接口发起明确操作，不直接访问文件或凭据。

原生取词优先评估旧版 selection-hook 模块，分别验证 Chrome、微信和 WPS 文字。自动取词失败保留用户主动复制后按快捷键调用的备用入口。模块与依赖的最终版本在实际验证后锁定。

Codex 使用本机 App Server。复用已有连接方式前检查握手、流式事件、停止、异常与临时问答行为。可选智谱／OpenAI 兼容 API 通过主进程 Electron session.fetch 发起 chat/completions 流式请求，沿用 Electron 系统网络路由；不增加其他 Agent 接入。

ProviderRouter 在每次请求开始时选择来源并冻结该请求的 API 地址、模型与 Key；在途请求不随设置变化切换，也不自动回退到另一服务。API 分帧解析 SSE 与 UTF-8，处理 [DONE] 或 stop 终态、空回答、断流、HTTP 错误、超时和 AbortSignal。Key 用 safeStorage 单独加密写入 model-key.enc，普通 preferences.json 和历史不含 Key；界面仅获得 hasApiKey。测试回答使用固定公开短句，不写历史、不保存设置。

自动查找 Codex 时尊重 PATH 中有效启动器的顺序，不跳过已安装 CLI 选择其他安装位置的内部二进制。子进程保留已有代理环境；未指定 HTTPS/ALL 代理时使用 Electron 解析的系统 HTTP/HTTPS 代理，不修改系统设置。翻译在当前请求指定 low 思考档位，其他问答沿用 Codex 设置；速度以公开样例实测为准。

## 模块与接口

- 桌面层：管理工具条、一个固定结果窗、一个临时结果窗、设置和系统托盘。
- 问答层：以独立 conversationId 管理原文、消息、最后主动请求时间和运行状态；窗口仅持有正在展示的 conversationId。
- 回答适配器：提供连接检查、发起生成、流式输出、完成/失败通知和停止接口；调用方明确传入目标问答及请求标识。
- 本地记录层：读取、更新、删除和按最近 100 条规则清理记录。原文、消息与设置放在本机应用数据目录，不放入项目目录或 Git。
- 界面层：工具条、问答详情、历史列表、设置。近期记录的状态字段不呈现在列表中。

## 数据与任务流

选区 → 工具条 → 用户执行操作 → 创建或继续独立问答 → 主进程调用选中的来源 → 按问答身份分发增量 → 更新对应记录和正在显示它的窗口。

显示状态与执行状态分离。收起或切换窗口不停止任务；发送/停止按钮绑定当前显示的问答，不能按全局任务状态决定。后台任务完成后仅更新记录，不抢占窗口。

本机历史保存原文、操作、用户问题、回答、最后主动请求时间与恢复所需状态。使用带版本字段的 JSON 文件和原子替换写入；生成内容节流落盘，完成、停止和失败时立即保存。程序意外退出后将未完成记录标记为中断，不自动重新提交。

恢复本地记录时，由回答适配器重建该问答需要的上下文；不以大量 Codex 长期会话代替工具本机历史。运行期临时会话及恢复方式必须在安装版本上验证。

## 复用与限制

旧代码按模块检查、择优复用，不整套恢复旧功能。专门检查旧代码中关闭窗口导致停止请求、每次回答重启进程、窗口级状态混用等与本版交互相关的行为。

保持文本问答用途，限制 Codex 执行无关本地命令、读取文件或调用工具，实际权限配置需验证。Codex 凭据由已有登录管理；API Key 仅从用户输入单向传入主进程并加密存储，不回传渲染界面，不写入日志或源码。不得自动解密或复制其他软件保存的 Key。

## 验证顺序

开发阶段先验证：三个目标应用的真实取词；Codex 实际流式回答及临时会话历史行为；多个独立问答的后台执行与准确停止。之后接入确认的 UI，完成本地记录和打包验收。

静态 Demo 仅使用示例数据和页面状态切换，验证视觉及交互表达，不证明真实应用取词、Codex 接入或持久化通过。
