# 拾句：前端视觉与交互规范

版本：1.0；日期：2026-10-23；状态：Demo 视觉与交互规范已确认。

适用范围：当前离线 Demo，以及后续桌面客户端的界面实现。以 `demo/index.html` 的实际呈现为依据；本文统一组件标准，真实取词、Codex 连接和持久化需在桌面程序中另行验收。

## 1. 设计目标与范围

产品是一种阅读辅助工具。划词后的操作应短、轻、可立即使用；结果以正文为主，辅助信息和操作不与正文争夺注意力。

- 优先压缩重复信息、空白占位和装饰，再调整组件尺寸；正文保持可读。
- 同一操作在不同场景中使用相同图标、尺寸、提示与交互。
- 信息保存在数据层，并不意味着它必须常驻界面。记录时间用于排序，列表中的时间仅辅助定位。
- 保留已有任务规则：新问答不取消后台回答，发送与停止共用操作位，近期记录不显示任务状态。
- Demo 的顶部导航、应用示例、场景说明属于预览控制台；示例文章属于模拟的外部应用。它们不进入正式划词工具的产品窗口。

## 2. 基础样式

### 字体与文字层级

使用系统字体：Segoe UI、Microsoft YaHei UI、Microsoft YaHei、sans-serif。所有尺寸为 CSS 逻辑像素；Windows 显示缩放与浏览器缩放会改变实际屏幕占用。

| 层级 | 字号 / 行高 | 用途 |
|---|---|---|
| 正文 | 14 / 22.4 | AI 回答、译文 |
| 内容与标题 | 13 / 20 左右 | 记录摘要、输入框、浮窗标题；标题字重 600 |
| 控件与原文 | 12 / 18；工具条标签 14 / 20 | 工具条标签、原文引用、快捷提问、语言菜单、设置项、异常提示 |
| 辅助信息 | 11 / 16～18 | 相对时间、数量、设置说明、原文展开入口 |

回答段落间距为 8。生成中与生成结束采用相同的正文排版。产品窗口不使用 15～17px 的引导大字，也不通过降低正文字号来容纳更多内容。

示例文章的 20～24px 标题和 16～18px 英文属于外部内容模拟，不是产品组件字号。

### 间距、圆角与控件

| 项目 | 规范 |
|---|---|
| 间距基本刻度 | 4、8、12、16、24 |
| 图标与短标签 | 4 |
| 同组控件、正文段落 | 8 |
| 内容区之间 | 12 |
| 浮窗正文左右内边距 | 16 |
| 常规图标 | 14 × 14；下拉箭头 12 × 12 |
| 图标按钮 | 可点击区域 28 × 28 |
| 带文字按钮 / 菜单项 | 快捷提问、设置按钮、菜单项至少 32 高 |
| 圆角 | 控件 6，菜单 / 工具条 / 输入框 8，浮窗 / 弹窗 12 |
| 描边 | 1px；原文引用竖线 2px |

输入框垂直内边距使用 6px，以容纳 28px 操作按钮并形成 42px 的总高度。这是控件尺寸适配，不新增一套内容区间距标准。

### 颜色与状态

| 角色 | 颜色 |
|---|---|
| 主文字 | `#303640` |
| 辅助文字 | `#6b7482` |
| 浮窗背景 | `#ffffff` |
| 控件浅背景 | `#f4f6f8` |
| 描边 | `#e5e8ee` |
| 强调 / 焦点 | `#526ad5` |
| 选中浅背景 | `#edf1ff` |
| 危险操作 | `#a34d4d` |

使用同一套轻阴影。悬停采用浅色背景，选中采用强调色；普通辅助文字仍应清晰可读。禁用发送按钮可弱化，启用操作不借用禁用色。键盘聚焦显示 2px 焦点轮廓。

样式源：HTML 中的 `:root` 定义字号、间距、颜色、圆角、图标与控件尺寸变量；组件优先引用这些变量。

## 3. 组件尺寸与内容规则

| 组件 | 尺寸与布局 | 常驻信息 | 按需信息 |
|---|---|---|---|
| 划词工具条 | 标签 14px / 20，图标 18px，按钮高 28；按钮水平内边距 8，外层内边距 4，总高 38 | 翻译、问 AI、复制 | 悬停、焦点反馈 |
| 浮窗框架 | 桌面默认 380×510；可从边缘调整，常规最小 320×300；圆角 12；标题栏高 40 | 功能标题、近期记录、固定、收起 | 固定状态高亮；记住最近窗口大小，适配屏幕工作区 |
| 原文引用 | 12px / 18，两行折叠；左侧内边距 8；下间距 12 | 选区内容 | 实际超出两行才显示展开；展开后显示收起 |
| 初始问 AI | 引用后直接排列快捷按钮 | 解释、润色、输入框 | 用户输入的问题 |
| 目标语言 | 12px，按钮至少高 28；菜单宽 128，选项至少高 32 | 自动识别 → 当前目标语言 | 展开菜单、当前选项勾选 |
| 用户问题 | 12px / 18，圆角 8；右侧 28×28 复制图标 | 已发送的问题、对应问题的复制按钮 | 长文本自然换行；悬停与无障碍名称为复制问题 |
| 回答 / 译文 | 14px / 22.4，段落间距 8 | 已生成正文 | 正常生成仅保留光标，不显示连接中或等待模型的文字；重连、失败另行提示，停止仍可用 |
| 回答操作 | 28 × 28 图标按钮，组间距 4，与正文间距 8 | 复制、重新生成图标 | 悬停名称与无障碍名称；翻译与问 AI 相同 |
| 输入框 | 字号 13px，行高 20，最小高 42，圆角 8；外侧左右边距 12、底边距 12 | 输入区、右侧发送 / 停止位 | 空输入禁用发送；生成中保留草稿 |
| 近期记录 | 每行至少高 36；摘要 13px，右侧时间 11px；间距 8 | 一行摘要与相对时间 | 摘要溢出省略，悬停显示完整内容；删除在悬停 / 聚焦时出现 |
| 记录底栏 | 至少高 36，左右内边距 16 | 数量 / 100、清空记录 | 删除确认 |
| 设置窗口 | 跟随桌面宿主大小，默认宽 380，圆角 12；标题栏高 48；内容侧边距 16；分组间距 16 | 回答来源、语言偏好、使用偏好 | Codex 登录检查；API 地址、模型、Key 密码输入及公开回答耗时测试；底部保存固定，表单独立滚动 |
| 删除确认 | 13px 正文，侧边距 16；按钮高 32 | 删除范围、取消、确认删除 | 涉及运行任务时说明后果 |
| 异常提示 | 12px 正文，内边距 12，圆角 8 | 可理解的原因与重试 | 详细错误只在需要诊断时展开 |

设置中的表单选择框使用表单样式；浮窗语言选择使用快捷菜单样式。二者共享字号、圆角、描边与交互状态，尺寸依使用场景区分。

桌面工具条的 38px 为目标内容高度；Windows 缩放取整后，页面应填满实际内容区，圆角外透明，不保留多余白色矩形。默认上方居中、不足时向下翻转，并限制在选区末端所在显示器的工作区内。多行端点不代表完整横向边界，不据此宣称侧边没有文字。

## 4. 显示必要性判断

| 信息 / 元素 | 决策 | 用途 |
|---|---|---|
| 浮窗中的原文 | 保留，默认两行 | 核对本次处理对象，避免在多个问答之间混淆 |
| 初始页大标题和解释性副标题 | 移除 | 解释、润色按钮和输入框提示已表达下一步操作 |
| 工具条文字 | 保留 | 三个入口必须能够直接辨认 |
| 回答下方操作文字 | 改为图标，悬停提供名称 | 属于重复使用的辅助动作；保留可发现性与可访问名称 |
| 自动识别与目标语言 | 保留为一行 | 告知翻译方向，并提供修改入口 |
| 时间数据 | 保留 | 排序、清理及定位记录所需 |
| 列表中的时间 | 保留右侧相对时间 | 支持找回近期记录，不单独占行 |
| 精确日期时间 | 悬停查看 | 普通浏览不需要精确到时分秒 |
| 历史任务状态 | 列表不展示 | 记录摘要与时间足以支持查找；过程与异常在详情呈现 |
| 空记录的占位高度 | 随内容自然收缩 | 避免几条记录撑起大块空白 |
| 已停止详情提示 | 简短保留 | 解释回答为何结束；不影响历史列表样式 |
| 空输入禁用发送 | 保留 | 明确可执行条件，防止误发 |
| 全局 Demo 说明 | 一处简洁常驻 | 表明内容为示例、未连接 Codex、刷新不保存 |

时间显示是当前产品方案，不代表所有同类工具的统一惯例。查看记录与复制不更新时间；更新时间仍由用户主动提问、重试等行为决定。

## 5. 自适应与滚动

- 预览画布使用可用宽高，不设置 910px 固定最小宽度。页面和画布不产生横向滚动；场景导航在窄屏可横向滚动。
- 文章区、回答区、历史列表分别在自身区域滚动。浮窗标题栏与输入框固定在窗口内。
- 单窗宽度不超过画布减去 24px；默认距画布边缘 12px，预览浏览器栏下留出操作位置。
- 两个结果窗在可用宽度不超过 820px 时并排等宽；不超过 580px 时上下排列。此行为用于窄预览区，桌面端仍须依据真实工作区实现定位。
- 窗口收窄后，已拖动的浮窗重新约束在可见区域内。工具条根据实际尺寸定位，边缘保留至少 8px。
- 语言菜单独立显示在上层，避免被回答滚动区裁切。菜单位置保持在当前视口内。
- 短视口优先保留产品控件，可收起预览场景说明与页脚。
- 不使用整体缩放来模拟紧凑界面；应真实控制字号、间距和控件尺寸。

## 6. 交互与可访问性

- 图标按钮提供明确的 `aria-label` 和悬停名称；翻译复制为“复制译文”，AI 回答复制为“复制回答”。
- 语言菜单支持方向键、Home / End、Enter；Escape 优先关闭菜单并返回触发按钮，之后才可收起临时窗。
- 选择当前语言只收起菜单，选择另一语言才重新翻译；仍属于同一条记录。
- 外部点击关闭菜单；用户滚动回答区或调整视口时关闭菜单，避免菜单与入口错位。
- 键盘能到达历史删除按钮，聚焦时显示操作；隐藏操作仍保留布局空间，避免时间与摘要跳动。
- Enter 发送、Shift+Enter 换行；中文输入法组合输入时不误发送。
- 焦点、悬停、选中、禁用和生成中均有明确样式。减少动态效果偏好下停止光标动画。

## 7. 验收与实现边界

运行 `node demo/verify-ui.cjs` 复核浏览器布局和关键交互。脚本需要本机 Playwright 与 Chrome / Edge，可通过 `UI_BROWSER` 指定浏览器路径。

检查范围包含宽屏、676×595 当前预览尺寸、更窄和更短的视口；工具条与浮窗边界、单双窗布局、原文与长回答滚动、输入框可用、语言菜单命中与键盘操作、历史单行显示及后台生成隔离。

`demo/ui-verification.json` 保存最近一次检查结果，`demo/audit-*.png` 保存对应截图。自动检查通过后仍需人工查看截图与用户体验确认。操作系统缩放、原生窗口、真实跨应用取词不由浏览器检查替代。

当前规范已通过用户的 Demo 体验确认，作为桌面开发的视觉基准。后续变更需同步 Demo、规范与验收项；此确认不代表真实桌面功能已完成。

### 回答正文与复制反馈（2026-10-27）

正文支持基础 Markdown 标题、加粗、列表、引用与代码，沿用现有正文字号和间距；代码块内部横向滚动。流式更新不附加打字机延时。模型 HTML 不执行，外部图片不加载，链接以文字显示。复制成功不弹提示；失败继续显示错误。解释首次默认两三句直接讲含义，不复述选区或主动铺陈长清单，追问按需展开。
